# IAM и доступы

## Роли людей

### `Администратор облака`

- создаёт ресурсы;
- выдаёт роли;
- контролирует billing и безопасность.

### `Разработчик`

- разворачивает код;
- читает логи;
- проверяет конфиг;
- не должен вручную управлять пользовательскими данными без необходимости.

### `Пользователь продукта`

- работает только через UI;
- не заходит в облачную консоль.

## Сервисный аккаунт приложения

Приложению нужен отдельный сервисный аккаунт, который умеет:

- читать и писать в `Object Storage`;
- вызывать `Cloud Functions` или быть назначенным им;
- читать и писать в `Message Queue` по своей роли;
- обращаться к `SpeechKit`;
- обращаться к `YandexGPT`.

## Переменные окружения

Минимально стоит предусмотреть:

- идентификатор приватного бакета;
- идентификатор публичного бакета;
- идентификатор очереди;
- параметры SpeechKit;
- параметры YandexGPT;
- флаги окружения `dev/stage/prod`.

## Секреты

В секретах или защищённом конфиге должны храниться:

- API-ключи / токены для интеграций;
- служебные идентификаторы, если их нельзя светить в открытом конфиге.

## Наблюдаемость

Нужно иметь возможность:

- открыть логи API-функции;
- открыть логи worker-функции;
- сопоставить ошибку с `meetingId`;
- понять, на какой стадии произошёл сбой.
