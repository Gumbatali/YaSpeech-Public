# YaSpeech — протоколы встреч без ручной расшифровки

YaSpeech превращает аудиозапись совещания в готовый протокол: кто что сказал,
о чём договорились, какие задачи и сроки. Загрузили запись — через несколько
минут получили структурированный документ. Сделано для строительной компании
СТРОЙТЕХЭКСПЕРТ, работает в Яндекс Облаке.

---

## Простыми словами

Представьте планёрку на стройке: прораб, заказчик, снабженец — десять человек
час обсуждают сроки, бетон, документы. Через неделю никто не помнит, кто
обещал привезти арматуру и к какому числу.

Раньше, чтобы это не терялось, кто-то должен был сидеть и вручную
расшифровывать запись, выписывать решения и задачи. Это часы работы.

**YaSpeech делает это сам.** Вы загружаете аудиофайл встречи, а сервис:

1. **расшифровывает речь в текст** — распознаёт, кто что говорил;
2. **исправляет ошибки распознавания** — понимает по смыслу, что «исполниловка»
   это «исполнительная документация», а не набор звуков;
3. **разделяет реплики по спикерам** и пытается определить, кто есть кто;
4. **собирает протокол** — краткий обзор, список участников, принятые решения и
   задачи с ответственными и сроками.

Результат можно **поправить руками** прямо в браузере, если сервис где-то
ошибся, и **пересобрать протокол** заново.

## Что умеет

| Возможность | Что это даёт пользователю |
|-------------|---------------------------|
| Загрузка аудио | Поддерживает MP3, M4A, WAV, OGG, FLAC и голосовые из мессенджеров |
| Автоматическая расшифровка | Текст встречи без ручного труда |
| Разделение по спикерам | Видно, кто какую реплику произнёс; у каждого свой цвет |
| Определение имён и ролей | Сервис пытается понять, где прораб, где заказчик; если не вышло — описывает роль в разговоре |
| Таймкоды | У каждой реплики время от начала записи |
| Две версии текста | «Дословно» (как распознала система) и «LLM восстановил» (с исправленными ошибками) |
| Редактирование расшифровки | Можно поправить любой фрагмент текста вручную |
| Возврат к оригиналу | Если правки не нужны — одной кнопкой вернуть исходную расшифровку |
| Готовый протокол | Обзор, участники, решения, задачи с ответственными и сроками |
| Редактирование итогов | Любой пункт протокола можно изменить прямо в интерфейсе |
| Память проекта | Сервис помнит прошлые встречи: переносит невыполненные задачи и накапливает словарь терминов проекта |
| Личные кабинеты | Вход по логину и паролю, у каждого свои проекты |
| Лимиты и роли | Администратор управляет пользователями и квотами на число расшифровок |

## Как этим пользоваться

1. **Войти** по логину и паролю (логином может быть имя или почта — на выбор).
2. **Создать проект** — например, конкретный строительный объект.
3. **Добавить команду** проекта (необязательно) — помогает точнее определять
   спикеров.
4. **Загрузить запись** встречи.
5. **Подождать** обработку — статус меняется автоматически.
6. **Проверить черновик** — поправить имена спикеров и название встречи.
7. **Получить протокол** — скопировать, скачать или отредактировать.

## Как устроено (для технических читателей)

YaSpeech — это тонкая веб-оболочка и оркестратор вокруг облачных AI-сервисов
Яндекса. Само приложение не распознаёт речь и не пишет текст — оно принимает
действия пользователя, хранит данные, управляет очередью обработки и собирает
результат в понятный интерфейс.

### Поток обработки

```
Браузер                Яндекс Облако
───────                ─────────────
загрузка файла  ──►  Object Storage (хранилище)
                         │
                         ▼
                     Message Queue (очередь задач)
                         │
                         ▼
                     Cloud Function «worker»
                         ├─ SpeechKit ───────► расшифровка речи
                         ├─ LLM-диаризация ──► разделение спикеров
                         ├─ коррекция ASR ───► исправление ошибок распознавания
                         ├─ определение имён ► кто есть кто
                         └─ YandexGPT ───────► сборка протокола
                         │
                         ▼
                     Object Storage (готовый протокол)
                         │
браузер  ◄── API Gateway ◄── Cloud Function «api»
```

### Архитектурные слои

- **`packages/core`** — доменная модель и сценарии использования. Чистая
  бизнес-логика, ноль зависимостей от облака. Здесь живут `meeting`, `project`,
  `user` и use-cases.
- **`apps/server`** — инфраструктура: адаптеры к Object Storage, SpeechKit,
  YandexGPT, очереди; HTTP-обработчик; сессии и хеширование паролей.
- **`apps/web`** — SPA на React + htm (без шага сборки), статика лежит в
  Object Storage.

### Технологии

- **Среда выполнения:** Node.js 18 на Yandex Cloud Functions (serverless).
- **Хранилище:** Yandex Object Storage (S3-совместимое) — данные в JSON и аудио.
- **Очередь:** Yandex Message Queue (асинхронная обработка).
- **Шлюз:** Yandex API Gateway (маршрутизация + лимиты запросов).
- **Распознавание речи:** Yandex SpeechKit (опционально Groq Whisper).
- **Языковая модель:** YandexGPT (многопроходный пайплайн коррекции и сборки).
- **Авторизация:** сессии на HMAC-SHA256 в httpOnly-cookie, пароли через
  `scrypt`. Без внешних npm-зависимостей — только встроенные модули Node.

Принципиальное решение: **облачные функции не используют npm-пакеты** — только
стандартная библиотека Node. Поэтому деплой — это просто архив с исходниками,
без `node_modules`.

## Запуск локально

Для локальной разработки backend поднимается с mock-адаптерами (без реальных
облачных вызовов) и хранит данные в JSON на диске.

```bash
npm test        # прогнать тесты
npm run build   # собрать
npm run dev     # запустить локально
```

После `npm run dev` приложение доступно на http://127.0.0.1:8787

Поведение управляется переменными окружения:

| Переменная | Назначение |
|------------|------------|
| `USE_MOCKS` | `true` — mock-адаптеры вместо реальных облачных сервисов |
| `ASR_PROVIDER` | `speechkit` \| `groq` \| `mock` — движок распознавания речи |
| `SESSION_SECRET` | секрет для подписи сессионных токенов |
| `ADMIN_LOGIN` | логин, который при регистрации получит роль администратора |

## Развёртывание в Яндекс Облаке

Деплой автоматизирован скриптом. Секреты лежат в `scripts/.env.deploy`
(не коммитится в git — см. `scripts/.env.deploy.example`).

```bash
./scripts/deploy.sh all       # обе функции + фронтенд + шлюз
./scripts/deploy.sh api       # только api-функция + фронтенд + шлюз
./scripts/deploy.sh worker    # только worker-функция
./scripts/deploy.sh gateway   # только конфигурация API Gateway
```

Подробности — в [облачном развёртывании](./docs/project-handbook/05-delivery-and-operations/cloud-deployment.md).

## Проверка качества распознавания

В `scripts/benchmark/` лежит инструмент для замера качества ASR: берёт аудио с
известными эталонными расшифровками (например, из открытого датасета Golos),
прогоняет через живой сервис и считает метрики WER/CER. См.
[scripts/benchmark/README.md](./scripts/benchmark/README.md).
