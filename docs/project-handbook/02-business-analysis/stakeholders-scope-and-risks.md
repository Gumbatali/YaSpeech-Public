# Стейкхолдеры, границы и риски

## Основные стейкхолдеры

- `Заказчик / владелец продукта`
  отвечает за видение, бюджет и приоритеты.
- `Менеджер`
  отвечает за сроки, ожидания и передачу между участниками.
- `Пользователь`
  загружает запись встречи и получает протокол.
- `Solution-архитектор`
  отвечает за технический контур и облачную схему.
- `Системный аналитик`
  отвечает за сценарии, контракты и модели данных.
- `Разработка`
  реализует UI, API и интеграции.
- `Cloud / DevOps`
  разворачивает и обслуживает решение в Yandex Cloud.

## Границы решения

Решение отвечает за:

- загрузку и хранение аудиозаписи;
- запуск пайплайна обработки;
- отображение статуса;
- выдачу черновика и финального протокола.

Решение не отвечает за:

- первичную запись аудио;
- идентификацию пользователя по аккаунту;
- интеграцию с календарями и мессенджерами;
- безошибочное распознавание личности каждого спикера.

## Ключевые ограничения

- использовать только те технологии, которые уже допустимы в проектном контуре;
- минимизировать облачные расходы;
- ориентироваться на mobile-first интерфейс;
- не привязывать MVP к конкретному мессенджеру;
- не строить отдельную полноценную БД в первой версии.

## Основные риски

### 1. Риск неточного определения спикеров

Даже если система делит речь на `Спикер 1`, `Спикер 2`, имена могут определяться неуверенно.

Смягчение:

- использовать команду проекта как контекст;
- показывать только черновик;
- оставлять возможность подтверждения пользователем.

### 2. Риск роста стоимости

Стоимость может вырасти, если:

- добавить лишние LLM-вызовы;
- гонять большие файлы через неподходящие сервисы;
- строить избыточную инфраструктуру.

Смягчение:

- один основной AI-шаг после транскрипта;
- serverless-контур;
- прямой upload в Object Storage.

### 3. Риск нехватки доступов

Для облачного запуска нужны роли и сервисные аккаунты.

Смягчение:

- заранее проверить IAM;
- отдельно описать матрицу доступов;
- не откладывать проверку `SpeechSense` и `AI Studio` на финальный момент.

### 4. Риск несоответствия ожиданий по “магии AI”

Пользователь может ожидать стопроцентного распознавания имен и ролей.

Смягчение:

- позиционировать результат как `черновик`;
- встроить шаг подтверждения перед финальным протоколом.
