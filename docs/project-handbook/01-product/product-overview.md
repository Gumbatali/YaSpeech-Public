# Обзор продукта

## Цель

Сделать простой веб-сервис, который помогает команде загрузить запись встречи и быстро получить:

- транскрипт;
- черновое название встречи;
- черновое определение спикеров;
- итоговый протокол встречи.

## Проблема

Сейчас запись встречи сама по себе не превращается в удобный рабочий артефакт. Чтобы получить результат, человеку приходится:

- слушать запись повторно;
- вручную писать summary;
- вручную выделять решения и задачи;
- хранить историю встреч в разрозненном виде.

## Ценность MVP

MVP должен закрыть базовую цепочку:

1. выбрать проект;
2. загрузить запись;
3. дождаться черновика;
4. подтвердить результат;
5. получить готовый протокол.

## Возможности

Базовый сценарий:

- список проектов и команда проекта;
- загрузка одного аудиофайла (MP3, M4A, WAV, OGG, FLAC, голосовые из мессенджеров);
- асинхронная обработка в облаке;
- черновик названия встречи и спикеров;
- финальный протокол, скачивание `TXT`, история встреч проекта.

Расшифровка и редактирование:

- две версии текста — «Дословно» (сырой ASR) и «LLM восстановил» (с коррекцией ошибок);
- разделение по спикерам с устойчивыми цветами и таймкодами;
- определение имён и профессиональных ролей, а если не вышло — роли в диалоге;
- ручное редактирование расшифровки и возврат к оригиналу;
- пересборка протокола на основе исправленного текста.

Итоги и память проекта:

- редактирование протокола (обзор, участники, решения, задачи со сроками);
- сверка с предыдущим протоколом и перенос невыполненных задач;
- накопление словаря терминов проекта для точности распознавания.

Пользователи и доступ:

- авторизация по логину и паролю, личные кабинеты;
- роли и администрирование: блокировка, назначение роли, квоты на расшифровки;
- ограничение частоты запросов на эндпоинтах входа (анти-брутфорс).

Развёртывание:

- production-интеграции с Yandex SpeechKit и YandexGPT (mock-слой остаётся для
  локальной разработки);
- работа в Яндекс Облаке: Object Storage, Message Queue, Cloud Functions, API Gateway.

## Что пока не входит

- запись аудио из браузера в реальном времени;
- автоматические интеграции с мессенджерами (приём голосовых из чатов);
- совместное (многопользовательское) редактирование протокола в реальном времени;
- реальная диаризация по звуковой дорожке (pyannote) как основной механизм —
  сейчас при моно-записи спикеров разделяет LLM по тексту.

## Продуктовые принципы

- пользователь не должен разбираться в технических деталях AI-пайплайна;
- главный сценарий должен работать с телефона;
- интерфейс должен вести человека по одному основному действию за раз;
- система может предлагать черновики, но не должна притворяться, что знает всё точно.
