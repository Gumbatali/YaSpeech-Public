# Diarization service contract

Все бэкенды диаризации (pyannote HF, NeMo Sortformer, Streaming Sortformer,
diart, EEND-EDA, self-hosted pyannote) говорят на одном HTTP-контракте.
Это позволяет менять бэкенд одной переменной окружения и сравнивать их
между собой в бенчмарке.

## POST /diarize

Запрос — `multipart/form-data`:

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| `audio` | file | да | Аудиофайл (WAV PCM 16 kHz mono предпочтительно) |
| `num_speakers` | int | нет | Точное число спикеров, если известно |
| `min_speakers` | int | нет | Нижняя граница (игнорируется бэкендами с фиксированными слотами) |
| `max_speakers` | int | нет | Верхняя граница (игнорируется бэкендами с фиксированными слотами) |

Ответ — `application/json`:

```json
{
  "backend": "nemo-sortformer",
  "model": "nvidia/diar_sortformer_4spk-v1",
  "audio_duration_sec": 312.4,
  "processing_time_sec": 18.2,
  "num_speakers_detected": 3,
  "segments": [
    { "speaker": "SPEAKER_00", "start": 0.51, "stop": 3.22 },
    { "speaker": "SPEAKER_01", "start": 3.10, "stop": 7.84 }
  ]
}
```

### Инварианты сегментов

- `start` и `stop` — секунды от начала записи, float.
- `stop > start` строго. Сегменты нулевой длины отбрасываются сервисом.
- Сегменты **могут перекрываться** — это overlapped speech, а не ошибка.
  Именно ради перекрытий существуют multi-label модели (Sortformer, EEND).
- Порядок сегментов — по возрастанию `start`.
- `speaker` — непрозрачная строка. Никакой семантики в номере нет: `SPEAKER_00`
  в двух разных запусках — разные люди. Сопоставление с реальными именами
  делает отдельный LLM-проход выше по пайплайну.

## GET /health

```json
{ "status": "ok", "backend": "nemo-sortformer", "device": "cuda", "model_loaded": true }
```

Возвращает 503, пока модель не загружена в память. Деплой-скрипты ждут
именно этого эндпоинта, а не просто открытого порта: загрузка весов на
холодном старте занимает десятки секунд.

## Ошибки

Любая ошибка — HTTP 4xx/5xx с телом `{"error": "...", "backend": "..."}`.

Node-адаптеры **никогда не роняют пайплайн** из-за ошибки диаризации:
`diarize()` возвращает `null`, и встреча обрабатывается без разделения
по спикерам. Это осознанный выбор — протокол без спикеров полезнее,
чем отсутствие протокола.
