# IAM и доступы

## Роли людей

### `Администратор облака`

- создаёт ресурсы;
- выдаёт роли;
- контролирует billing и безопасность.

### `Разработчик`

- разворачивает код;
- читает логи;
- проверяет конфиг;
- не должен вручную управлять пользовательскими данными без необходимости.

### `Пользователь продукта`

- работает только через UI;
- не заходит в облачную консоль.

## Сервисные аккаунты

### Рантайм-аккаунт приложения — `yaspeech-sa`

Назначается обеим Cloud Functions. Роли: `storage.editor`, `ymq.writer`
(+ доступ к SpeechKit и YandexGPT). Умеет:

- читать и писать в `Object Storage`;
- читать и писать в `Message Queue`;
- обращаться к `SpeechKit` и `YandexGPT`.

### Deployer-аккаунт для CI — `yaspeech-deployer`

Отдельный SA, от имени которого GitHub Actions выкатывает код. Роли:
`functions.editor`, `api-gateway.editor`, `iam.serviceAccounts.user` на
`yaspeech-sa`. Не имеет доступа к пользовательским данным сверх необходимого для
деплоя. Настройка — в [ci-cd.md](./ci-cd.md).

## Переменные окружения функций

Задаются при деплое (`deploy.sh`):

| Переменная | Назначение |
|------------|-----------|
| `YC_STORAGE_BUCKET` | приватный бакет артефактов |
| `YC_QUEUE_URL` | URL очереди YMQ |
| `YMQ_KEY_ID` / `YMQ_SECRET` | статический ключ доступа (S3 + YMQ) |
| `YC_FOLDER_ID` | каталог в YC |
| `SESSION_SECRET` | соль для подписи сессионных cookie |
| `ADMIN_LOGIN` | логин первого администратора |
| `GPT_MODEL` | модель YandexGPT для основных стадий (по умолчанию `yandexgpt-lite`) |
| `GPT_MODEL_REFINE` | модель для «Улучшить расшифровку» (по умолчанию `yandexgpt` — Pro) |

## Секреты

- Локально — `scripts/.env.deploy` (в `.gitignore`, не коммитится).
- В CI — GitHub Secrets (см. [ci-cd.md](./ci-cd.md)).
- В коде секретов нет — только переменные окружения.

### Ротация ключей

При утечке или плановой ротации статического ключа SA:

1. Создать новый ключ доступа для `yaspeech-sa`.
2. Обновить `KEY_ID`/`SECRET` в `scripts/.env.deploy` и в GitHub Secrets.
3. Передеплоить функции (новые версии получат новый ключ в окружении).
4. Удалить старый ключ в консоли YC.

> Историческая заметка: один SA-ключ был ротирован после попадания в git-историю.
> Любой ключ, попавший в коммит, считается скомпрометированным — ротировать
> обязательно, удаления из истории недостаточно.

## Наблюдаемость

Логи обеих функций пишутся в Cloud Logging автоматически; записи содержат
`meetingId` и стадию, что позволяет связать ошибку с конкретной встречей.
Подробнее — в [monitoring-and-logging.md](./monitoring-and-logging.md).
