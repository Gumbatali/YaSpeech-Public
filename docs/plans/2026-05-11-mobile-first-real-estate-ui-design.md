# Mobile-First Real Estate UI Design

**Date:** 2026-05-11

## Goal

Упростить интерфейс так, чтобы им было удобно пользоваться с телефона. Приложение должно ощущаться как спокойный рабочий инструмент для недвижимости, а не как многослойный дашборд.

## Core Direction

Берём `mobile-first` и строим интерфейс как `2 отдельных экрана`:

1. `Экран проектов`
2. `Экран выбранного проекта`

Это позволяет убрать визуальный шум и оставить только один главный сценарий на каждом экране.

## Screen 1: Projects

- Короткая шапка.
- Заголовок `Проекты`.
- Кнопка `Новый проект`.
- Простой список проектов карточками.

На этом экране не показываем:

- встречи;
- команду проекта;
- инструкции на несколько абзацев;
- обработку записи.

## Screen 2: Project

Содержит только необходимые вещи:

- шапка с `Назад`, названием проекта и кнопкой `Люди проекта`;
- главный рабочий блок;
- короткий список `Последние встречи`.

Главный рабочий блок переиспользуется для разных состояний:

- `Загрузить запись`
- `Идёт обработка`
- `Черновик встречи`
- `Готовый протокол`

Таким образом экран проекта остаётся одним и тем же местом, а пользователь не блуждает по множеству разделов.

## What We Remove

- Перегруженную hero-композицию.
- Слишком крупную и агрессивную типографику.
- Параллельный показ многих карточек сразу.
- Второстепенный контекст рядом с главным действием.
- Декоративный шум, конкурирующий с контентом.

## Mobile-First Interaction

На телефоне приоритет такой:

1. выбрать проект;
2. выбрать файл;
3. дождаться черновика;
4. подтвердить и получить протокол.

Поэтому на проектном экране главным должен быть один понятный CTA:

- `Выбрать файл`
- затем `Загрузить запись`

## Visual Direction

Тема продукта — недвижимость, поэтому фон и визуальный язык должны отсылать к архитектуре, а не к абстрактным AI-паттернам.

Выбранное направление:

- светлый тёплый фон;
- тонкие линии архитектурного чертежа;
- спокойные тени;
- аккуратные карточки;
- меньше контрастных декоративных блоков.

Фон делаем как code-native SVG asset, чтобы:

- не усложнять сборку;
- легко использовать в облачном хостинге;
- контролировать лёгкость и читаемость на телефоне.

## Success Criteria

- Пользователь не теряется на главном экране.
- С телефона главный сценарий читается без прокрутки по множеству разнотипных секций.
- Кнопка выбора файла очевидна.
- Проектный экран показывает только одно главное действие и короткую историю встреч.
- Интерфейс выглядит аккуратно и “по недвижимости”, но не мешает работе.
