# Навигация: YaSpeech — автопротоколирование деловых встреч

**Сервис протоколирования встреч на Yandex Cloud**: SpeechKit (ASR, разделение говорящих по `channelTag`) + YandexGPT (многоходовый анализ, включая LLM-диаризацию) + Object Storage (хранение артефактов). Кукбук основан на архитектуре реального продакшн-сервиса YaSpeech и показывает упрощённую, но рабочую Python-версию пайплайна для Colab/Jupyter.

## Best Practices

1. **Многоходовый анализ вместо одного промпта**
   - Разбивайте задачу на узкие проходы: контекст → коррекция → идентификация → генерация
   - У каждого прохода своя температура: коррекция консервативна (0.15-0.25), сводка чуть свободнее
   - Ошибка одного прохода не должна портить остальные

2. **Защита от потери данных при коррекции текста**
   - Line-ID протокол (`[N] текст`) вместо JSON — модель не может незаметно выкинуть реплику
   - Детерминированный валидатор чисел — не полагайтесь только на промпт-инструкции для критичных фактов
   - Retry на чанк при обнаружении пропущенных ID, а не тихий fallback на исходный текст

3. **Диаризация по реальным данным, а не только по акустике**
   - Передавайте в промпт список участников проекта (имена + роли), если он у вас есть
   - Явно указывайте модели на признаки: обращения по имени, характерная лексика роли
   - Всегда возвращайте уровень уверенности (`high`/`medium`/`low`) — не выдавайте догадку за факт

4. **Негативные ограничения в промптах протокола**
   - "Пустой массив лучше, чем выдумка" — явно прописывайте это в system prompt
   - Требуйте дословных цитат там, где это важно (принятые решения, ключевые моменты)

5. **Обработка ошибок**
   - SpeechKit-операции асинхронны — оборачивайте поллинг таймаутом
   - Ловите `JSONDecodeError` при парсинге ответов LLM — модель иногда оборачивает JSON в markdown
   - Логируйте количество отклонённых валидатором правок — это сигнал качества промпта

6. **Масштабирование**
   - Для длинных встреч — map-reduce: кусками по репликам, слияние + один консолидирующий вызов
   - Разносите старт распознавания и поллинг операции по отдельным serverless-вызовам
   - Чекпоинтите прогресс REFINE-прохода — длинные встречи не должны начинаться с нуля при таймауте
