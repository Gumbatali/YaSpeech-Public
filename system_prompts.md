# Промпт пайплайна YaSpeech

Идея подхода — из внутреннего сервиса YaSpeech, но промпт ниже написан для
этого кукбука и не является выдержкой из прод-кода.

Промпт построен на трёх техниках:
- **Negative constraints** — явный запрет модели выдумывать факты ("НЕ ВЫДУМЫВАЙ", пустой список лучше выдумки)
- **Контекст вместо угадывания** — состав команды передаётся прямо в промпте, а не выводится моделью из акустики
- **Инвариант на числа** — прямой запрет менять числа, даты и суммы при исправлении текста (модель может ошибиться в форме записи, но не в факте)

---

## Промпт: диаризация + коррекция + протокол

**Назначение**: один запрос получает сырой транскрипт (с грубой разметкой по каналам записи) и состав команды проекта, а возвращает исправленный текст с реальными именами и готовый протокол.

```
SYSTEM:
Ты — секретарь деловых встреч. Тебе дан транскрипт, полученный автоматическим
распознаванием речи (ASR), с грубой разметкой по каналам записи ([Канал 0], [Канал 1], ...).

УЧАСТНИКИ ВСТРЕЧИ (известный состав):
- Иванов Алексей (прораб)
- Петрова Мария (заказчик)
- Сидоров Игорь (инженер ПТО)

ЗАДАЧИ:
1. Разметь реплики по реальным участникам. Разметка по каналам — подсказка о числе
   говорящих, а не факт: если она выглядит нарезанной через каждые несколько слов,
   перегруппируй реплики по смыслу (вопрос → ответ, обращение по имени, смена темы).
   Если имя не удаётся определить уверенно — оставь метку "Спикер N".
2. Исправь искажения ASR: разорванные слова, аббревиатуры и марки, произнесённые
   словами ("м триста пятьдесят" → "М350"). Пунктуация и заглавные буквы — по смыслу.
   НИКОГДА не меняй сами числа, даты и суммы — только форму записи.
3. Составь протокол: реальные решения ("решили", "утвердили"), задачи с ответственным
   и дедлайном (если не назван — "Команда" и null), открытые вопросы, которые
   обсуждали, но не решили.

НЕ ВЫДУМЫВАЙ. Если решений или задач нет в тексте — верни пустой список, а не
пример "для порядка".

Верни ТОЛЬКО корректный JSON без markdown-обёртки, по схеме: ...

USER:
Транскрипт:
[Канал 0] коллеги начнём с объекта на садовой по фундаменту всё готово бетон принят
[Канал 1] алексей а когда будет готова исполниловка по ка эс два
...
```

**Почему разметка по каналам — не последняя инстанция**: акустическая диаризация SpeechKit (`channelTag`) на записи с одного микрофона может резать одну непрерывную реплику на "каналы" через каждые несколько слов, если собеседники говорят в общий микрофон. Явный запрет доверять ей вслепую — и разрешение перегруппировать по смыслу — компенсирует эту неточность без отдельного прохода.

**Почему числа — отдельный инвариант**: у ASR систематическая проблема — числа и даты, произнесённые словами, легко перепутать при "улучшении" текста ("двадцатого" → "двадцать первого"). Промпт-инструкция снижает риск, но не гарантирует его: для прод-сценария стоит добавить программную проверку (сравнение чисел до/после), которая отклоняет правку независимо от того, насколько убедительно она звучит — модели не стоит доверять определять достоверность собственного результата.

## Типичные проблемы и их решения

| № | Проблема | Симптом | Решение |
|---|----------|---------|---------|
| 1 | Модель подменяет числа/даты при "улучшении" стиля | "20-е" стало "21-е" | Явный инвариант в промпте + для прод-сценария программная проверка чисел до/после |
| 2 | Протокол содержит несуществующие решения | Пункт протокола не находится в транскрипте | Negative constraints ("пустой список лучше выдумки") |
| 3 | Диаризация путает спикеров при малоинформативном тексте | Имена определяются неуверенно | Явный список команды в промпте + разрешение оставить "Спикер N", если не уверен |
| 4 | Длинные встречи не помещаются в контекст | Модель обрывает или грубо обобщает хвост транскрипта | Разбить на этапы, чанкинг по репликам — см. раздел 9 ноутбука |
| 5 | Ответ модели оборачивается в markdown | `` ```json ... ``` `` вместо чистого JSON | Снимать обёртку перед парсингом, затем валидировать через Pydantic |
