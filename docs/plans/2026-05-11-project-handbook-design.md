# Project Handbook Design

**Date:** 2026-05-11

## Goal

Собрать в проекте единый пакет документации, который можно передавать:

- менеджеру;
- системному аналитику;
- solution-архитектору;
- разработчику;
- DevOps / cloud engineer;
- новому участнику команды.

## Direction

Берём формат `project handbook` в отдельной папке `docs/project-handbook/`.

Материалы делим не по исходным файлам, а по ролям и видам проектной информации:

1. `01-product`
2. `02-business-analysis`
3. `03-solution-architecture`
4. `04-system-analysis`
5. `05-delivery-and-operations`
6. `06-development`

## What Must Be Included

- обзор продукта и границы MVP;
- пользовательские сценарии;
- стейкхолдеры, ограничения, риски, допущения;
- функциональные и нефункциональные требования;
- solution-архитектура;
- классические диаграммы уровня `C4`;
- последовательности обработки аудио;
- жизненный цикл встречи;
- доменная модель;
- API-карта;
- модель хранения данных;
- схема облачного развёртывания;
- IAM и доступы;
- runbook;
- handoff-материалы для разработки.

## Diagram Format

Диаграммы оформляем в `Mermaid` прямо в markdown, чтобы они:

- хранились рядом с кодом;
- легко редактировались;
- не требовали отдельного графического редактора;
- были пригодны для handoff и ревью.

Дополнительно добавляем один HTML-обзор архитектуры для презентационного использования.

## Documentation Principles

- всё на русском языке;
- тексты короткие, но рабочие;
- отражаем `текущее состояние MVP`, а не абстрактную целевую систему;
- отдельно помечаем `что уже реализовано`, `что мокировано`, `что является целевой облачной схемой`.
